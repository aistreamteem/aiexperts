**Captured:** 2026-11-08

**Status:** active

**Starter / guess until they teach.**

An authorization number is copied only from their payer letter, portal print, or form image. Typical US PT claim rows need that number when the plan issued one. If it is missing, ask. Do not invent a number so the claim or day list looks complete. Do not reuse last year’s number. Do not promise the plan approved payment because a number exists — quote the letter’s status words. Starter / guess until they teach which field *this* clinic treats as the live auth number. A number on a sticky note they did not save as a letter image is a question, not an auth you copy.

## 2026-11-08: Authorization as paperwork
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/physical-therapy-front-role/docs/facts/auth.md
**Status:** active

**Starter / guess until they teach.**

Authorization at this role is a paperwork file: payer letter or portal print, reference number as printed, dates of validity as printed, visit or unit count as the letter already shows, and whether attachments their process listed are in the folder. Typical US PT clinics chase commercial visit auths and some Medicare Advantage prior-auths this way. You do not write the clinical argument. You do not pick CPT so the auth “fits.” You do not invent an authorization number. You do not invent remaining visits from a phone call you did not save. Quote the letter’s status words — approved, pending, denied, more-information — as printed, not as a promise of payment. If the letter’s dates or visit count do not cover the booked visit, flag and ask; do not silently rebook. CMS prior-auth pages are orientation only. Starter / guess until they teach which payers *this* clinic tracks on the auth log. An approved auth is still not a guarantee the next booked visit will pay.

## 2026-11-08: How this role files work items
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/physical-therapy-front-role/docs/facts/how-we-file.md
**Status:** active

**Starter / guess until they teach.**

Day-to-day work does **not** go in one shared pile. Each **work item** gets its own folder under `work-items/<id>/` so Tuesday does not overwrite Monday, and one appointment does not mix with the next.

Typical name for *this* role (until they confirm a different pattern):

- **What one folder is:** appointment or named patient-day (chart id)
- **How to name it:** `work-items/2026-09-15-0900-chart-18/`
- **Pattern:** `work-items/YYYY-MM-DD-HHMM-chart/`

Inside every item folder:

- `in/` — files they dropped for *this* item only
- `work/` — scratch while this item is in progress
- `out/` — the finished list or write-up for *this* item
- `evidence/` — check logs for this item only

Auth remaining packs can be one insurance-list they named. Prefer chart number.

If they already file another way (their software’s id, a property code, a period name), **use their words**. Ask before starting if it is unclear which item this is. Never dump new files into yesterday’s folder. Never put two appointments, two tickets, or two periods in the same item folder unless they asked for a combined pack and named it that way (for example one day-list).
