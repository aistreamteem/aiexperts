### 2026-11-08: Appointment type
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/medical-clinic-front-role/docs/facts/appointment-type.md
**Status:** active

**Starter / guess until they teach.**

Appointment type on a typical US clinic book is a scheduling label: new, established follow-up, physical, well-child, sick, procedure, nurse-only, lab-only, telehealth, worker-comp, or a custom type they created. The type drives duration, intake packet, and sometimes which room or resource they hold. It is not a diagnosis and not a CPT you choose. Copy the type as their EHR or book stored it. Do not relabel a sick slot as a physical, or a telehealth type as in-office, to make the day look tidy. Do not invent a visit type because the reason field sounds like one. If type is blank, say blank and ask; do not fill “office visit” from habit. Duration attached to a type comes from their template or schedule rules file, not from a remembered fifteen-versus-thirty guess. A type that usually needs a referral or prior-auth paperwork is a completeness flag only when their process names that type — you still do not decide medical necessity. One type per booked row unless they use a combo type they already stored. Starter / guess until they teach *this* clinic’s type list and durations.

### 2026-11-08: How this role files work items
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/medical-clinic-front-role/docs/facts/how-we-file.md
**Status:** active

**Starter / guess until they teach.**

Day-to-day work does **not** go in one shared pile. Each **work item** gets its own folder under `work-items/<id>/` so Tuesday does not overwrite Monday, and one appointment does not mix with the next.

Typical name for *this* role (until they teach a different pattern):

- **What one folder is:** appointment (or one clinic-day list)
- **How to name it:** `work-items/2026-09-15-1015-chart-2201/`
- **Pattern:** `work-items/YYYY-MM-DD-HHMM-chart/`

Inside every Work Item folder:

- `in/` — files they dropped for *this* item only
- `work/` — scratch while this item is in progress
- `out/` — the finished list or write-up for *this* item
- `evidence/` — check logs for this item only

Prefer chart number. A day list is `work-items/YYYY-MM-DD-day-list/`. Do not copy extra clinical notes into the folder. Journals for the same id live under `journals/work-items/<id>/`.

If they already file another way (their software’s id, a property code, a period name), **use their words**. Ask before starting if it is unclear which item this is. Never dump new files into yesterday’s folder. Never put two appointments, two tickets, or two periods in the same item folder unless they asked for a combined pack and named it that way (for example one day-list).
