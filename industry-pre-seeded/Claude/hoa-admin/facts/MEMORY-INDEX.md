# Memory System Index

Quick navigation for this HOA / association admin Expert. Load only the operations files plus the active Work Item facts/rules.

---

## Two axes: browsing and triggers

1. **Workflow axis** (this file) — load operations memory for this role’s registered jobs.
2. **Trigger axis** ([TRIGGER-INDEX.md](TRIGGER-INDEX.md)) — action-time surfacing. `TRIGGER-INDEX.md` and `trigger-index.json` are generated by `python scripts/memory/build_trigger_index.py`. Do not hand-edit them.

---

## Pre-seeded role

**Role title:** HOA / association admin

**Seed id:** `hoa-admin`

**Work-item method:** `docs/role/work-item-method.md`

Day-to-day role memory lives in the **operations** pair:

- [facts-operations.md](facts-operations.md)
- [rules-operations.md](rules-operations.md)

There is no software-pipeline or incident-bridge memory for this role.

### Operations (association admin)

**When to use:** Any Work Item under `work-items/WID-*` — ACC completeness, violations, dues aging, board files, bid compare, vendor certs, work orders, election tally, reserve index.

**Load these files:**

- [facts-operations.md](facts-operations.md) — lots, governing-doc quoting, violation logs, bids, meeting files, dues, ACC forms, certificates, work orders, reserves, and related starter facts
- [rules-operations.md](rules-operations.md) — must-never rules (no legal stamp, no demand letter, no ACC approval, no fund movement, label guesses, …)

**Typical context load:** operations pair only (plus MEMORY-INDEX and the active Work Item `facts/` folder).

### Work Item memory

**When to use:** Facts and rules that apply only to this meeting, application, lot, or pack.

**Load:** `work-items/<id>/facts/facts.md` and `work-items/<id>/facts/rules.md` when they exist.

## Entry Format Reference

### Fact Entry Template

```markdown
### YYYY-MM-DD: Descriptive Title

**Scope:** expert-role

**Workflows:** all | acc-completeness | violations | dues-aging | board-files | bid-compare | vendor-certs | work-orders | election-tally | reserve-index

**Captured:** YYYY-MM-DD

**Source:** <where this came from>

Descriptive content about what this is, how it works, what it means...
```

### Rule Entry Template

```markdown
### YYYY-MM-DD: Prescriptive Action Title

**Scope:** expert-role

**Workflows:** all | <registered workflow id>

**Triggers:** write:doc | write:csv | none

**Captured:** YYYY-MM-DD

**Source:** <where this came from>

**Rule:** Clear statement of what MUST be done

**Why:** Rationale

**How to apply:**

1. Step-by-step procedure
```

### Usage Tips

1. Always load this index first, then the operations pair.
2. Load Work Item facts/rules for the active `WID-*`.
3. Registered jobs are listed in `.claude/workflows/workflow-registry.json`.
