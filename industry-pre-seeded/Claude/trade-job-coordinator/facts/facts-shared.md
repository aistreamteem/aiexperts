### 2026-11-08: Callback / warranty return
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/trade-job-coordinator/docs/facts/callback.md
**Status:** active

**Starter / guess until they teach.**

A callback is a return to a recent job, usually the same equipment, the same symptom, or a promised adjustment, rather than a brand-new sale. Typical office flags include a day window they already use, same tech versus a senior tech, and whether the visit is billed or no-charge. Shops differ on how many days count and whether the return uses a job type or a child work order; ask their definition and how they code it on the board. Warranty labor and manufacturer parts warranty are not the same clock. Do not bill a flagged return like a new demand sale unless they marked it billable. Do not admit fault as a legal warranty or write that the shop breached a statute. Do not invent a no-charge decision to calm a customer. Quote the original job id, the return job id if they opened one, the symptom in their words, and the bill mark they already stored. If the file is silent on bill versus no-charge, that silence is a question for the person who owns pricing, not a guess.

### 2026-11-08: How this role files work items
**Scope:** expert-role
**Workflows:** all
**Captured:** 2026-11-08
**Source:** seeds/trade-job-coordinator/docs/facts/how-we-file.md
**Status:** active

**Starter / guess until they teach.**

Day-to-day work does **not** go in one shared pile. Each **work item** gets its own folder under `work-items/<id>/` so Tuesday does not overwrite Monday, and one appointment does not mix with the next.

Typical name for *this* role (until they correct a different pattern):

- **What one folder is:** service ticket (or crew day / sold pack they named)
- **How to name it:** `work-items/WID-20260915/` (or the WID they give)
- **Pattern:** `work-items/WID-XXXXXXXX/`

Inside every Work Item folder:

- `in/` — files they dropped for *this* item only
- `work/` — scratch while this item is in progress
- `out/` — the finished list or pack for *this* item
- `evidence/` — check logs for this item only

Parts and the dispatch list for that ticket stay in that folder. A whole-day board can be its own Work Item if they asked for the day, not one ticket.

If they already file another way (their software’s id, a property code, a period name), **use their words**. Ask before starting if it is unclear which item this is. Never dump new files into yesterday’s folder. Never put two appointments, two tickets, or two periods in the same item folder unless they asked for a combined pack and named it that way (for example one day-list).
