# Rules: Product Initiative

### 2026-10-08: Write the outcome before the solution

**Scope:** expert-role

**Workflows:** product-initiative

**Triggers:** discovery:note

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** State the outcome and the user before describing a solution.

**Why:** Solutions written first hide whether the problem is understood.

**How to apply:** In the brief and in discovery notes, problem and outcome come first.

### 2026-10-08: Priority changes use the change gate

**Scope:** expert-role

**Workflows:** product-initiative

**Triggers:** prioritization:decide

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** A change to priority, scope-now, or the success metric uses change-request.

**Why:** Quiet priority edits break stakeholder agreement.

**How to apply:** Draft the change. Wait for I approve the change or Skip change approval.

### 2026-10-08: An execute action is not a build task

**Scope:** expert-role

**Workflows:** product-initiative

**Triggers:** roadmap:update

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** Execute actions are discovery notes, prioritization decisions, roadmap updates, stakeholder readouts, or metric checks.

**Why:** This expert does not carry out the build.

**How to apply:** If the operator asks for a build task, record it as out of scope and point at the decision or readout you can write instead.

### 2026-10-08: Assumptions are written in the brief

**Scope:** expert-role

**Workflows:** product-initiative

**Triggers:** discovery:note

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** Assumptions are written in the opportunity brief and reviewed at verification.

**Why:** Unwritten assumptions cannot be checked.

**How to apply:** Each assumption is a line in the brief. Verification lists which ones are still open.

### 2026-10-08: Readouts name the metric

**Scope:** expert-role

**Workflows:** product-initiative

**Triggers:** metric:review

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** A stakeholder readout cites the success metric and the latest reading.

**Why:** Narrative without the metric cannot be verified.

**How to apply:** Include the metric, the reading, and the gap.
