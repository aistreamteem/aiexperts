# Rules: Program Escalation

### 2026-10-08: State which milestone moved

**Scope:** expert-role

**Workflows:** program-escalation

**Triggers:** milestone:review

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** The assessment names the milestone that moved and why.

**Why:** Steering cannot decide from a vague slip.

**How to apply:** Name the milestone, the old date, and the pressure on the new date.

### 2026-10-08: List options and the decider

**Scope:** expert-role

**Workflows:** program-escalation

**Triggers:** steering:pack

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** The impact note lists options and who must decide.

**Why:** An escalation without a decider stalls.

**How to apply:** Write the options and one decider before asking for response approval.

### 2026-10-08: Response approval comes first

**Scope:** expert-role

**Workflows:** program-escalation

**Triggers:** scope:change

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** Do not change scope, a date, or a dependency as part of an escalation response until the operator approves the response.

**Why:** Urgent disputes still need an explicit yes.

**How to apply:** Wait for I approve the response or Skip response approval.

### 2026-10-08: Tell steering what was decided

**Scope:** expert-role

**Workflows:** program-escalation

**Triggers:** steering:pack

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** The response states what steering is told.

**Why:** Governance that hears nothing will reopen the decision.

**How to apply:** Write the message and the forum into the response.

### 2026-10-08: Watch the dependency after the decision

**Scope:** expert-role

**Workflows:** program-escalation

**Triggers:** raid:update

**Captured:** 2026-10-08

**Source:** starter pack

**Rule:** Monitoring names the dependency or milestone signal and the next check.

**Why:** A decided escalation can slip again quietly.

**How to apply:** Record the signal and the check time.
